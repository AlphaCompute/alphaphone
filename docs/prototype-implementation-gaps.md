## Concrete unfinished prototype journeys

- **Photos:** multi-select → Favorite/Delete and video → Edit still report unavailable. Owned-photo rotate/crop/filter → Save copy is now implemented and has scoped acceptance; it must not remain listed as missing.
- **Notes:** supported text → selected SAF destination and selected UTF8 file → new note now have native acceptance. Cloud sync, conflict recovery, rich-note backup/import and physical speech-to-transcript remain different journeys.
- **Notifications:** own channel Settings recovery now works. Other-app summaries/notification actions still need explicit listener consent, app selection, redaction and revoke. The current shade shows active Alpha notifications, not a complete OS or durable cross-app history.
- **Workflows:** Change edits name/description only; New and the full trigger/action palette cannot create a safe executable workflow yet. Removal is receipt-preserving and Restore returns paused; neither erases historical effects nor replaces a trigger scheduler policy.
- **Inbox:** compose/reply can retain encrypted local drafts, but provider draft save/send/reply, attachment/thread management and ambiguous delivery reconciliation remain unsupported. No real email acceptance is inferred from the closed test account.
- **Browser/passwords:** read-aloud, booking and the current browser sharing callback remain unavailable in the adapter. Real vault setup/autofill/passkeys and production supported-WebView distribution remain separate from synthetic framework tests.
- **Maps/Calendar/Phone:** Maps is a configured regional development integration; global/offline/physical guidance is unqualified. Calendar invitations/account synchronization and actual call/SMS/voicemail journeys need their provider/role/device flows.

Prioritize terminal combined-session/restart evidence and final full-suite results,
then these concrete unfinished flows while preserving reference layout. Real
provider authorization, physical/manual accessibility and AOSP boot remain
explicit gates. Historical source descriptions below are retained as history,
not current capability claims.

## Historical highest-priority work — September 29

1. **P0 — Replace production fixture data with empty/loading/real-data states.** Production installs adapters, but much of `model.js` still supplies seeded contacts, messages, inbox, photos, files, wallet cards, workflow history, settings statistics and Home cards. 2. **P0 — Complete provider boundaries rather than treating callbacks as integration.** Current native callback interception is based on property names/paths in presentation render results. Wallet is mapped to the existing `passwords` context enum; treat that as a compatibility limitation, not a complete domain model.
4. **P1 — Complete real provider-backed app flows beneath the exact presentation.** Maps navigation, browser page controls, email inbox, calendar account data and contacts remain largely external handoffs. Exact Alpha screens need real native/provider data and completion receipts; an external app's screen does not satisfy that requirement by itself.
5. **P1 — Requalify lifecycle and receipts on the new renderer.** Source now has different persistence keys, routing, overlays and selection behavior. ## Historical architecture and implementation order

Keep fixture mode (`DEV`, non-Android, explicit `fixture=1`) for visual snapshots, and separate its datasets from production. Introduce typed view models with `unconfigured`, `loading`, `ready`, `stale`, `denied`, `failed` and `empty` status; render those states in the existing exact components. Keep only safe local preferences as local state; accounts, permissions, delivery, media and network/device facts come from real capability adapters.

Next implement a typed action registry with explicit payloads and return receipts, replacing heuristic callback interception domain by domain. Start with the already-working slices—notes, selected document, camera still photo, reminders, agent proposal/approval—then actual calendar/mail/contact models and owned Chromium/maps. Ensure every selected real entity updates the agent context with an opaque identity, account boundary, revision and sensitivity. Do not grant agent access merely because a presentation component is visible.

Tests should combine visual equality with actual flow outcomes on the same current phone APK: provider setup/denial → real data → detail → edit/draft → explicit approval where applicable → native/provider result → return/reload. Record unavailable external services as blockers. Keep device/AOSP/production identity acceptance distinct from renderer extraction, debug emulator integration and native handoff tests.
