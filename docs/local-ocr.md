# Local Camera Scan

Camera Scan captures and retains a photo, runs English OCR on this device, and opens an editable review dialog. Copy uses the clipboard only after a click. Save to Notes writes the corrected text through the existing Notes persistence boundary and reports success only after a confirmed commit. A failed or uncertain save retains the text and disables repeat submission. Scanning does not send pixels or text to the agent or a model provider.

The same renderer implementation and packaged assets are used by browser development and Android web assets. Actual Android WebView execution and physical camera accuracy remain unverified in this browser-only pass. English text extraction does not yet implement the design's document boundaries, event recognition, Add event, or automatic language selection. These remain open requirements, not simulated successes.

## Runtime and packaging

`local-ocr.ts` owns a classic Worker from creation through termination. It uses the pinned Tesseract.js 7.0.0 worker protocol because the high-level asynchronous createWorker call exposes its handle only after model initialization. The real-engine browser test checks that protocol. Leaving Camera, hiding the page, closing the dialog or pressing Back cancels and terminates the worker, including while loading the model. One recognition is bounded to 60 seconds; input is JPEG/PNG/WebP up to 16 MB and 32 million pixels, resized to a maximum 2048-pixel edge. Review text is limited to 100,000 characters. Recognition accuracy varies with focus, orientation and print quality; users review the result.

`local-ocr-assets.ts` serves an exact allowlist under `/ocr/` in development and emits the same files into `web-dist/ocr/` for packaging. The package lock pins worker 7.0.0, core 6.1.2 and English data 1.0.0. Scalar, SIMD and relaxed-SIMD LSTM cores contain their WASM; feature detection selects one. No CDN defaults are used. The compressed English integer model is approximately 2.95 MB; the three JavaScript/WASM cores total approximately 11.7 MB. Only one core loads per scan. Total packaged assets are approximately 14.8 MB; model caching is disabled in the OCR library.

Upstream API and local installation references: [Tesseract.js API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md), [local installation](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md). The worker and core license files ship beside the assets. The [tessdata repository Apache 2.0 license](https://github.com/naptha/tessdata/blob/gh-pages/LICENSE) is retained in `licenses/tessdata-APACHE-2.0.txt` and emitted with the model. The npm language package metadata separately declares MIT; it wraps the upstream trained data.

## Browser evidence

`test/browser/local-ocr.spec.ts` uses real Tesseract worker/WASM/model execution. It verifies recognizable generated print, local asset requests with no remote requests, early cancellation, Camera Scan through a synthetic camera stream with real JPEG/IndexedDB and Notes reload, retained text on an explicitly injected unconfirmed save, and cancellation while model loading is held. Synthetic camera pixels and injected persistence failures are test fixtures, not hardware evidence. Existing browser camera save/denial/late-permission cases are also rerun. No Android build is performed.

## Photo PDF export

The scan review now shows the captured image and offers **Download photo PDF** in a browser or **Save photo PDF** on Android. The generated document contains one image page, fitted without distortion inside A4 portrait or landscape margins. It includes the photo rather than corrected OCR text; the UI states this distinction. Reviewed corrections still use Save to Notes. Input is decoded locally, resized to a 2048-pixel longest edge, converted to JPEG and embedded with pinned `pdf-lib` 1.17.1, loaded on demand. Its MIT license ships with the local scan assets. See the [PDF-LIB image embedding API](https://pdf-lib.js.org/docs/api/classes/pdfdocument#embedjpg).

Browser export requests a real `.pdf` download and does not claim a confirmed filesystem save or automatic insertion into Browser files. Android calls the existing AlphaNoteDocuments plugin with a bounded PDF payload and an explicit `ACTION_CREATE_DOCUMENT` picker. It writes only the user-selected URI, reads the bytes back, and reports confirmed success only on exact equality. Provider write/readback failures remain unverified outcomes; the review prevents repeat export, except after an explicit picker cancellation. Closing or hiding the scan cancels PDF preparation before the document API is called. A picker/write already dispatched may still finish; closing the review does not reverse it.

Browser tests inspect the downloaded PDF structure and portrait/landscape geometry, verify a real image resource, cancellation and invalid input handling, and keep all action buttons inside the dialog at 360×740 dark and 1440×500 light. A Poppler-rendered landscape export was visually inspected, and text extraction was empty as expected for an image-only PDF. A host-Java harness exercises the same native payload/readback helper against malformed and oversized encoding, truncation, added bytes, changed bytes and non-progressing reads. This is not Android picker or device acceptance; no APK build was run. Automatic document boundary detection, event actions, multiple pages, searchable PDF text and additional languages remain open.

## Reviewed website links

Recognized or corrected text now supplies an expandable **Review links** list. Each entry shows its full normalized HTTP/HTTPS address before an explicit Open link action. Browser development uses a new tab with no opener or referrer; Android uses the existing browsable system-intent handoff. No address is fetched, prefetched, sent to the agent or opened merely because OCR detected it. Corrections immediately update the list, and retired or removed links cannot navigate through their old controls.

Detection handles explicit HTTP/HTTPS and `www.` tokens, quoted addresses, surrounding punctuation, duplicate URLs and international hostnames displayed in ASCII/punycode. It does not guess bare domains, join OCR lines or convert active schemes to search. Credentials, backslashes, malformed authority syntax and oversized candidates are excluded. At most ten unique destinations are shown; users can correct the source text. A recognized URL can still be misread, so the review asks users to compare the full address with the photo.

Tests use real OCR on a generated URL image and intercept the eventual destination with a local test response. They verify no pre-click request, correction replacing the destination, stale/retired controls failing closed, and a new page with `window.opener === null`. This qualifies the browser review and navigation path. Android intent dispatch is existing code; no new Android/device acceptance is claimed. Automatic event extraction, document boundary detection, multipage capture and searchable PDF text remain unfinished.

The URL test also exposed a real OCR character error in the generated sample hostname. The test now checks that the displayed destination matches the actual OCR result, then verifies explicit correction before opening. Link detection is not a guarantee of transcription accuracy.

Qualification for this link change: 77 repository tests, typecheck and production web build passed on the fixed candidate; 12 combined OCR/PDF/link browser cases passed. The two link cases were rerun after adjusting screenshot scroll position. No Android build was run.
