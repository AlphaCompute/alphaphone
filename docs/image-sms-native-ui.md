# Image-only Messages integration

The verified Alpha image admits the Messages view through `AlphaTelephony`. Standalone, browser and sideloaded launcher installs do not admit it. READ_SMS, SEND_SMS and phone-state permissions are separate explicit Android requests. No SMS role is claimed and no permission is pregranted by this change.

Conversation and message pages use a stable date/kind/row cursor, including SMS/MMS rows with equal timestamps. Provider nulls, unreadable text stored as an MMS attachment, oversized full bodies/addresses and oversized MMS part sets fail visibly instead of appearing empty or silently clipped. Thread snippets are explicitly previews. MMS attachment bytes and MMS sending remain with the system messaging app. Foreground observation and provider content are cleared when leaving the view; drafts never enter prototype persistence.

Direct SMS requires an explicitly selected active SIM. Alpha's native dialog shows exact recipients, body, SIM and part count, and rechecks access and SIM identity at dispatch. The system messaging-app handoff is a separate button; its UI owns the SIM and final send. Neither path sends automatically. A transport failure preserves the same operation ID for a repeated native review; editing starts a new explicit review. Native sent/delivery notices refresh the durable journal history. The recent Alpha send panel reads up to 200 encrypted journal records after restart, including unknown operations, without exposing stored recipients or body. The provider list separately shows device message history.

The native journal is encrypted in the existing credential store. Legacy plaintext journals are encrypted before removal. Up to 200 full records plus 1000 ID tombstones are retained. New work fails closed at the lifetime ID capacity or encrypted-slot capacity, preserving every previous idempotency key. Tombstones are never silently deleted. There is no automatic capacity reset or resend recovery. Existing system messaging applications remain available outside this ledger.

Content-based delivery attribution rejects duplicate provider candidates, incomplete enumeration, wrong SIM, claimed rows and overlapping identical operations. Once records have been pruned, attribution cannot exclude missing metadata and stays unknown. Multipart delivery stays unknown. Native submission is not sent or delivered evidence; ambiguous/partial failures are never retried automatically.

Shared agent `sms_send` integration requires the reviewed upstream `sms.send.v1` action/receipt contract and exact execution-claim operation ID. It remains a separate integration gate until the reviewed pin is consumed. No real message, emulator/image permission flow, carrier callback, MMS attachment or physical device acceptance was exercised by the source tests. Issue #421 remains open for those gates.
