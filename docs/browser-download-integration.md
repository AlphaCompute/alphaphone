# Native browser downloads

Build47 emulator checkpoint, 2026-09-30. Native compilation, lint and all four APK builds passed. Both standalone and launcher passed the actual Android DownloadManager flow: decline without queueing, approve and read exact bytes, reopen completion, cancel an active transfer, and preserve truthful HTTP failure. Evidence: `test-results/prototype-build47/focused/{standalone,launcher}.txt`. These fixture downloads use debug loopback HTTP; production HTTPS and redirect qualification remain separate. No complete download is claimed from JavaScript, a click, a queued ID or a notification alone.

The existing prototype browser menu has a native-controls-only Downloads row. Fixture mode retains the reference menu. Website attachment responses use the native WebView DownloadListener and an Android confirmation dialog reviewing destination origin, sanitized filename and advertised size (or unknown). The user may cancel before any DownloadManager request. The native callback checks that the originating tab and navigation revision are still current before enqueueing. A new navigation or tab destruction dismisses its pending review.

After confirmation, Android DownloadManager owns the transfer into public Downloads with a unique safe filename. Alpha does not forward browser cookies, authorization headers, referrers, user-agent state or form bodies. There is no automatic opening, execution or package installation. Authenticated, POST, blob and data-URL downloads remain outside this public-download slice; the browser does not export its profile credentials to make them work. The agent receives no download URLs, request headers, credentials or file bytes from this implementation.

Release accepts only HTTPS download URLs without userinfo or control characters. Debug builds additionally permit exact loopback HTTP fixture hosts. AOSP DownloadProvider enforces the calling package's cleartext policy while following redirects, and uses its TLS configuration. Alpha's release manifest disables cleartext; the debug policy provides the existing isolated loopback exception. Release redirect-downgrade and certificate-failure qualification remain distinct from the loopback test. [AOSP DownloadThread](https://android.googlesource.com/platform/packages/providers/DownloadProvider/+/refs/tags/android-16.0.0_r4/src/com/android/providers/downloads/DownloadThread.java).

The native Downloads dialog queries only locally recorded DownloadManager IDs. It displays provider-derived queued, downloading, waiting, complete, failed or removed states and actual byte counters. Active rows provide Cancel download, which calls DownloadManager.remove. Completed/failed rows provide Remove entry, which removes Alpha's history entry without deleting the user's downloaded file. History is bounded to 50 entries and persists IDs, safe names and source origins privately so the menu can reopen status after restart. No raw query strings or signed download URLs are persisted in that history. Android retains its own provider records as part of performing the transfer.

The confirmation's size is an advertisement, not a promise: the response can change and an unknown size is explicitly shown. Destination-origin review does not claim that a redirect cannot serve content from another HTTPS host. The current filename uses URLUtil plus a conservative ASCII filename filter, length limit, leading-dot removal and a unique prefix; untrusted Content-Disposition cannot select a path.

`BrowserDownloadInstrumentedTest#explicitReviewExactBytesDenialAndCancellation` uses an actual loopback HTTP server, native child attachment navigation and visible Android dialogs. It requires no DownloadManager row before approval or after denial, exact bytes from the real completed provider file, completion readback through the product menu, cancellation of a stalled transfer and an actual failed provider row after a 404. Tests remove only uniquely named synthetic rows/files/history; no real downloads or credentials are selected. Both APK variants must pass before calling this flow verified. Additional acceptance: release TLS/redirect behavior, persistence across process restart, external deletion, full disk/offline/resume, physical device and Files-provider discovery.
