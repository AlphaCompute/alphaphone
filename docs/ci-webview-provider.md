# Disposable CI WebView provider

The positive Android smoke fixture uses an unmodified, pinned Chromium development WebView. It is not the production provider selection or an update mechanism for users. The stock API35 image's WebView124 lacks APIs required by the positive browser flows. Version numbers and source declarations do not establish actual runtime feature support; hosted instrumentation must still pass.

The official AndroidDesktop_x64 snapshot1709176 maps to Chromium commit `b1bde56dbc71dd73916cb44c9270c37086379bdf`, version157.0.8083.0. Its [archive configuration](https://chromium.googlesource.com/chromium/src/+/b1bde56dbc71dd73916cb44c9270c37086379bdf/infra/archive_config/android-desktop-x64-archive-rel.json) includes SystemWebView.apk. `scripts/prepare-ci-webview.mjs` pins the object generation, archive size/SHA256, APK SHA256 and developer certificate. APK v2 verifies with the public development certificate; that is not production signing authority. The APK contains x86 and x86_64 libraries, minSDK29/targetSDK37, and no Trichrome static-library dependency.

The [official removal helper](https://chromium.googlesource.com/chromium/src/+/b1bde56dbc71dd73916cb44c9270c37086379bdf/android_webview/tools/remove_preinstalled_webview.py) was reviewed but is not executed: its Q+ branch removes Google WebView, Chrome and Trichrome. This AOSP fixture instead backs up and hashes exactly one stock124 `/product/app/webview/*.apk`, validates a fresh GitHub-hosted API35 x86_64 `test` AVD with user0 only, and removes only that verified file after writable-system remount. Framework startup is attempted in `finally`. Any failed admission or partial operation ends the job with evidence; it does not attempt broad cleanup or operate on another device.

The workflow prepares the stock display fixture first, then provisions the provider before product APK installation. Evidence records signature, SDK/ABI metadata, exact installed bytes, provider selection and RELRO completion. `runtimeFeaturesQualified` remains false in provisioning evidence: the subsequent browser instrumentation is the behavioral evidence. Keep unsupported-provider tests (notably `BrowserUnsupportedReadingInstrumentedTest`) on a separate unchanged stock fixture; its negative assertion is incompatible with the upgraded positive fixture.

The CI artifact retains the stock APK and compact provenance. Successfully verified candidate download/extraction files are removed from the artifact directory to avoid repeatedly uploading a large archive. The pinned upstream URL and hashes reproduce them. This work still requires a successful hosted run at its committed head; local admission controls and static artifact inspection are not hosted qualification.
