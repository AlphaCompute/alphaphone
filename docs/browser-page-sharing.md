# Native browser page sharing

The existing reference Menu → Share control now invokes Android's real chooser. The adapter closes its overlay and restores the isolated child WebView; native validation then requires the same browser session, selected tab, navigation revision and exact current URL, a visible committed document, no loading/error and no other outstanding share/file chooser. Navigation, tab hiding or privileged document replacement before dispatch rejects the request. The chooser snapshots the current page when opened; cancelling never claims that anything was sent.

The renderer passes only identity/revision guards. Native code reads the URL and title from its own current child WebView and sends `ACTION_SEND`, `text/plain`, exact URL as `EXTRA_TEXT` and title as subject/display title. Unsupported URL schemes, URL user information, control characters and oversized URLs are rejected. Oversized/control-bearing titles fall back to the host name. No cookies, form values, DOM, credential slots, URI grants, attachments, recipient addresses or automatically selected app are supplied. A URL can itself contain sensitive query/fragment text; explicit sharing sends the exact displayed page address without inventing a sanitized destination. The agent receives none of these share contents.

`BrowserShareInstrumentedTest#exactCurrentPageChooserCancellationAndStalePageRejection` is opt-in with instrumentation argument `browserShareLive=1`. It loads a unique public HTTPS example.com URL without disabling TLS, places synthetic private cookie/storage canaries in the isolated child, clicks actual reference controls, observes the outgoing intent without intercepting the chooser, checks exact title/URL and absence of canary/recipient/attachment/grants, waits for the real ChooserActivity, cancels with Back and requires the same page/storage to return. It then attempts the captured old navigation request after a new document and from another app; both must reject without launching another chooser. No recipient is selected and no message is sent.

TypeScript and whitespace checks are required at the source checkpoint; Android compilation and both distribution native executions remain pending. This does not establish delivery to a third-party recipient or every OEM chooser implementation. Existing mock-mode prototype behavior is unchanged; no template layout was altered.

Post-Build77 fixture refinement: canary cookie/storage keys now include a fresh UUID, so an existing site's named key is never overwritten. A scoped finally returns to the accessible owned child and removes only values still equal to this fixture's canary, verifying both keys absent. It never clears site storage/cookies broadly. If cleanup cannot access the page, its failure is reported (suppressed beneath an original flow failure when present), not silently ignored. Build77 artifacts remain unchanged; this test refinement requires a later build. Back injection and title assertions are unchanged pending actual Build77 results.
