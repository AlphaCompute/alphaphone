# Local Eliza app-host verification

`node scripts/start-local-remote.mjs` starts the actual existing Eliza app host with a private Alpha Phone profile. It uses `~/eliza-workspace/milady/eliza` by default; override `ALPHA_ELIZA_SOURCE`, `ALPHA_REMOTE_PROFILE`, or `ALPHA_REMOTE_PORT` when needed. The default endpoint is `http://127.0.0.1:47839`. The launcher allows exactly `10.0.2.2` as an additional HTTP Host for the Android emulator; the server remains bound to loopback. This allows emulator requests through upstream DNS-rebinding protection while preserving session authentication. Emulator access over cleartext HTTP to `10.0.2.2` needs a debug APK built with `npm run android:build -- --test-mocks` (from `artifacts/test-mocks/`); distribution APKs carry no cleartext network configuration. Do not run two processes against the same profile.

The launcher reads an owner-only `~/.config/alphaphone/cerebras-key`, selects direct Cerebras `qwen-3.8-27b`, disables Cloud inference and uses a fresh profile with scheduling/personal-assistant defaults disabled. It runs from the profile directory, not the source checkout, so upstream dotenv does not load checkout credentials. Logs and owner/pairing material belong only in the private profile. No source checkout is modified.

Read a fresh pairing code with the host's loopback-only `GET /api/auth/pair-code`; exchange its `code` and `instanceId` through `POST /api/auth/pair`. Never expose the owner token or pairing code in logs or screenshots. For an Android emulator, reverse port 47839 through ADB and configure the phone to use that endpoint. Stop the launcher gracefully to stop its child host.
